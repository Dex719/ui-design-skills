# 25. Формы и ввод данных: автозаполнение, вход, коды, деньги, даты, файлы

Источники: HTML Living Standard (autofill, `inputmode`, `enterkeyhint`), WCAG 2.2 (1.3.1, 1.3.5, 3.3.1–3.3.3, 3.3.7, 3.3.8), WebAuthn и passkeys (W3C, FIDO Alliance), WebOTP API, NIST SP 800-63B, Baymard Institute (checkout), NN/g (формы). Базовые правила форм — `references/07`, тексты ошибок — `references/13`.

**Главная мысль.** Лучшее поле — то, которое не пришлось заполнять. Дай браузеру и менеджеру паролей заполнить всё, что они знают, принимай ввод в любом разумном формате и форматируй сам.

## Автозаполнение: `autocomplete` у каждого поля

Без правильного `autocomplete` браузер угадывает поля по названиям и часто ошибается. Это ещё и критерий WCAG 1.3.5.

| Поле | `autocomplete` | Тип и клавиатура |
|---|---|---|
| Имя целиком / имя / фамилия | `name` / `given-name` / `family-name` | `type="text"` |
| Email | `email` | `type="email"` |
| Свой телефон | `tel` (или `tel-national` без кода страны) | `type="tel"` |
| Телефон получателя, контакта | `off` — иначе браузер подставит номер самого пользователя | `type="tel"` |
| Логин | `username` (+ `webauthn` для passkeys) | `type="text"` или `email` |
| Текущий пароль / новый пароль | `current-password` / `new-password` | `type="password"` |
| Код из SMS или приложения | `one-time-code` | `inputmode="numeric"` |
| Адрес | `street-address` или `address-line1`, `address-line2`; город `address-level2`; индекс `postal-code`; страна `country-name` | `type="text"` |
| Организация | `organization` | `type="text"` |
| Дата рождения | `bday` (или `bday-day`, `bday-month`, `bday-year`) | см. «Даты» |
| Карта | `cc-name`, `cc-number`, `cc-exp`, `cc-csc` | `inputmode="numeric"` |

- `autocomplete="off"` для этих полей не ставь: браузеры его часто игнорируют, а менеджеры паролей ломаются. Отключать стоит только для полей, где подсказки вредны (поиск по коду товара, капча).
- `name` и `id` полей — стабильные, одинаковые на всех шагах и страницах: по ним менеджеры паролей узнают форму.
- `enterkeyhint` на мобильном: `next` между полями, `done` в последнем, `send` в чате, `search` в поиске.

## Вход, регистрация, пароли

- **Passkeys (WebAuthn)** — основной путь, если продукт их поддерживает: поле логина с `autocomplete="username webauthn"` даёт браузеру показать сохранённые ключи прямо в подсказке (conditional UI). Пароль — запасной путь, не убирай его сразу.
- **Регистрация:** только то, что нужно сейчас; email или телефон — один, второй позже. Подтверждение email не блокирует первые шаги.
- **Пароль:**
  - кнопка «Показать пароль» (иконка `eye` / `eye-off`, `aria-pressed`) вместо поля «Повторите пароль»;
  - требования видны до ввода и отмечаются по мере набора (текстом, не только цветом);
  - не требуй смешивать заглавные, цифры и символы; разрешай длинные пароли (64+ символов), пробелы и вставку — так советует NIST SP 800-63B; проверяй по списку утёкших паролей;
  - минимальная длина — 8 символов, если есть второй фактор; если пароль — единственный фактор, NIST (ред. 4) требует не меньше 15.
- **Ошибка входа** не раскрывает, что именно неверно («Неверный логин или пароль»); логин после ошибки не стирается, пароль — можно.
- **Восстановление** доступно с экрана входа одной ссылкой; ссылка сброса ведёт сразу в форму нового пароля.
- WCAG 3.3.8: без когнитивных тестов (запомнить, переписать, решить задачу); вставка и менеджеры паролей работают; капча — с альтернативой.

## Одноразовые коды (OTP)

- **Одно поле** `autocomplete="one-time-code" inputmode="numeric" maxlength="6"` — его заполняют подсказка клавиатуры iOS и Android. Шесть отдельных клеток выглядят красиво, но ломают вставку, автозаполнение и скринридеры; если нужны клетки визуально — одно скрытое поле под ними.
- **WebOTP:** последняя строка SMS `@example.kz #123456` позволяет сайту получить код сам (Chrome на Android). Домен — точно твой.
- Отправка по заполнению всех цифр — можно, но с видимой кнопкой «Подтвердить» на случай ошибки.
- Таймер повторной отправки 30–60 с, затем «Отправить снова» и альтернативный канал («Позвонить», «Отправить на email»).
- Неверный код — поле очищается, фокус в нём, сообщение «Неверный код»; число попыток — только когда их осталось мало.
- Номер, на который ушёл код, показан, с ссылкой «Изменить номер».

## Телефон, ИИН и другие форматы Казахстана

- **Телефон:** `type="tel"`, свой номер — `autocomplete="tel"`, номер получателя — `autocomplete="off"`; по умолчанию код +7. Принимай `+7 701 234 56 78`, `87012345678`, `7012345678`, со скобками и дефисами — нормализуй сам и не пиши об этом под полем: формат показывает серый пример `+7 777 123 45 67`. Ошибка — одна на все случаи: «Неверный номер». Маска не мешает вставке и не прыгает кареткой.
- **ИИН / БИН:** 12 цифр, `inputmode="numeric"`, без маски-разделителей (так его печатают в документах). Последняя цифра — контрольная: проверяй на клиенте при уходе с поля, ошибка — «Неверный ИИН». Первые 6 цифр ИИН — дата рождения: не спрашивай её второй раз.
- **IBAN (KZ):** 20 символов, начинается с `KZ`; показывай группами по 4, принимай с пробелами и без, вставку — всегда.
- **Языки:** подписи и ошибки — на языке интерфейса; переключатель «Қаз / Рус» не стирает введённые данные.

## Деньги и числа

- **Сумма:** `inputmode="decimal"`, принимай и запятую, и точку, пробелы между разрядами. Форматируй **при уходе с поля**, а не на каждый символ — иначе каретка прыгает.
- **Валюта:** знак ₸ после числа через неразрывный пробел: `12 500 ₸`. В коде — `new Intl.NumberFormat("ru-KZ", { style: "currency", currency: "KZT", maximumFractionDigits: 0 })` или `kk-KZ` для казахского интерфейса.
- Знак валюты — вне поля (префикс или суффикс рядом), а не внутри значения, которое человек стирает.
- Лимиты — когда они важны: «Максимум 500 000 ₸» появляется, если сумма к нему приближается или его превысила. Итог с комиссией — пересчитывается сразу.
- **Карта:** номер группами по 4, проверка по алгоритму Луна, тип карты определяется по номеру (не спрашивай); срок — одно поле `ММ/ГГ`; CVC — `inputmode="numeric"`, подсказка где он на карте.
- **Двойная отправка:** кнопка оплаты после клика — `fx.loading` (без `disabled`, фокус остаётся), на сервере — ключ идемпотентности.

## Даты и время

- **Дата рождения и известные даты** — три поля (день, месяц, год) или одно с маской `ДД.ММ.ГГГГ`. Календарь-попап для даты рождения — плохо: листать 30 лет назад.
- **Ближайшие даты** (бронь, доставка) — календарь, но с возможностью ввести текстом; недоступные дни — видно почему.
- **Диапазоны** — один календарь с выбором начала и конца, выбранные дни подсвечены, длительность подписана («5 ночей»).
- `type="date"` — нативный выбор на мобильных, но формат и вид зависят от браузера; для форм с жёстким форматом — свои поля.
- Формат — по локали (`ДД.ММ.ГГГГ` для ru/kk), никогда не `MM/DD`. Время — 24 часа.
- Часовой пояс — указывать, если люди в разных поясах (Казахстан с 2024 года в одном поясе UTC+5 — проверяй актуальность для своего продукта).

## Выбор из вариантов

| Вариантов | Компонент |
|---|---|
| 2–5, важно видеть все | Радиокнопки (или сегменты для 2–4 коротких) |
| 6–15 | `select` или радио в два столбца |
| 15+ или поиск по названию | Combobox с поиском (страна, город, банк) |
| Несколько из многих | Чекбоксы; 15+ — список с поиском и чипами выбранного |
| Вкл./выкл. с мгновенным эффектом | Переключатель (switch) |
| Вкл./выкл., применится при отправке | Чекбокс |

- Группа радио и чекбоксов — `fieldset` + `legend` с вопросом.
- Значение по умолчанию — разумное и безопасное; согласия и подписки — **не** отмечены заранее (`references/15`).

## Адреса

- Одно поле с подсказками адреса + ссылка «Ввести вручную» на отдельные поля; подсказки не блокируют ввод адреса, которого нет в базе.
- Сначала страна (если их несколько) — от неё зависят поля и формат индекса.
- Квартира, подъезд, этаж — отдельные необязательные поля: курьеру они нужны, а в строке адреса теряются.
- Адрес доставки = адрес оплаты — чекбокс, отмеченный по умолчанию.

## Файлы

- Кнопка выбора + перетаскивание + вставка из буфера (для скриншотов). Нативный `input type="file"` с видимой подписью, стилизуется через `label`.
- **Типы и размер — до выбора:** «PDF или JPG, до 10 МБ». `accept` фильтрует диалог, но проверяй и после выбора.
- У каждого файла: имя, размер, прогресс, «Отменить» во время загрузки, «Удалить» после, превью для изображений. Ошибка — у конкретного файла, остальные остаются.
- Фото документов с телефона — `accept="image/*"` (камера или галерея); подсказка, как снять без бликов.
- Загрузка не блокирует остальную форму; отправка ждёт файлы и говорит об этом.

## Длинные и многошаговые формы

- Шаги по смыслу (данные → доставка → оплата), «Шаг 2 из 4» с названиями шагов. Назад — без потери введённого.
- **Черновик сохраняется** (локально или на сервере); при возврате — «Продолжить заполнение».
- Перед отправкой — сводка с «Изменить» у каждого блока.
- Ошибка сервера после отправки — данные на месте, ошибки у полей и в сводке, фокус на сводку.

## Доступность форм

- У каждого поля — `label` (связан через `for`/`id`); плейсхолдер лейблом не считается.
- Подсказка и ошибка связаны с полем через `aria-describedby` (подсказка остаётся, ошибка добавляется — так делает `fx.fieldError`); `aria-invalid="true"` у ошибочного поля.
- Обязательные поля — атрибут `required` и текст («обязательное» или звёздочка с расшифровкой в начале формы).
- Сводка ошибок — список ссылок на поля; фокус переходит на сводку.
- Ошибка — текстом и иконкой, не только красной рамкой (WCAG 1.4.1, 3.3.1).
- Не проси повторно то, что человек уже ввёл в этом процессе (WCAG 3.3.7).
- На мобильном поле при фокусе прокручивается в видимую область, клавиатура не закрывает кнопку отправки; шрифт поля ≥ 16 px (иначе iOS увеличивает страницу).

## Чек-лист

- [ ] У каждого поля правильные `type`, `inputmode`, `autocomplete`, `enterkeyhint`.
- [ ] Вставка работает везде; менеджеры паролей и passkeys заполняют вход.
- [ ] Телефон, ИИН, IBAN, суммы принимаются в любом разумном виде и форматируются при уходе с поля.
- [ ] OTP — одно поле с `one-time-code`; есть повторная отправка и смена номера.
- [ ] Даты — по локали, без календаря для дня рождения.
- [ ] Ошибки рядом с полем, текстом, с решением; данные не стираются; есть сводка.
- [ ] Двойная отправка невозможна; черновик длинной формы не теряется.
- [ ] Согласия не отмечены заранее.

## Анти-паттерны

- Запрет вставки в поле пароля, кода или email.
- Шесть отдельных клеток для кода без поддержки вставки.
- Маска, которая не даёт вставить номер `8 701…` или переставляет каретку.
- «Повторите email» и «Повторите пароль».
- Календарь для даты рождения, открывающийся на текущем месяце.
- Ошибка «Неверный формат» без серого примера формата в поле.
- Абзацы пояснений под полями («номер можно вставить в любом виде»).
- `autocomplete="off"` на логине и адресе.
