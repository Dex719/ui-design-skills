# 12. Доступность (WCAG 2.2 и практика)

Источники: W3C WCAG 2.2 и Understanding-документы, W3C «Using ARIA», web.dev (focus), WCAG 3 Working Draft (сентябрь 2026), EN 301 549 / European Accessibility Act.

## Статус стандартов (2026)

- **Норма — WCAG 2.2 уровня AA.** EAA (с 28.06.2025, покрывает онлайн-банкинг и e-commerce в ЕС) через EN 301 549 ссылается на WCAG 2.1 AA.
- **WCAG 3** — рабочий черновик (10.09.2026), до финала годы; алгоритм контраста не определён, APCA не нормативен.

## Новое в WCAG 2.2

| Критерий | Уровень | Суть |

| 2.4.12 Focus Not Obscured (Enhanced) | AAA | Не перекрыт даже частично |
| 2.4.13 Focus Appearance | AAA | Индикатор ≥ периметра толщиной 2 CSS px, контраст 3:1 между состояниями |

## Самые важные критерии из 2.0/2.1 для дизайна

- 1.1.1 — текстовые альтернативы (alt), см. `10-web-media-performance.md`.
- 1.3.1 — структура передаётся семантикой (заголовки, списки, таблицы, лейблы).
- 1.4.1 — информация не только цветом.
- 1.4.3 / 1.4.11 — контраст текста 4.5:1, UI 3:1.
- 1.4.4 — зум до 200% без потери функций; 1.4.10 — reflow на 320 CSS px.
- 1.4.12 — интервалы текста (см. `05-typography.md`).
- 1.4.13 — тултипы при hover/focus: можно закрыть (Esc), можно навести на сам тултип, не исчезают сами.
- 2.1.1 — всё доступно с клавиатуры; 2.1.2 — нет клавиатурных ловушек.
- 2.2.1 / 2.2.2 — таймауты и движение под контролем пользователя.
- 2.3.1 — не больше 3 вспышек в секунду.
- 2.4.3 — логичный порядок фокуса; 2.4.7 — фокус виден.
- 3.3.1 / 3.3.3 — ошибки описаны текстом с подсказкой исправления.
- 4.1.2 — у контролов есть имя, роль, состояние; 4.1.3 — статусные сообщения объявляются.

## Клавиатура и фокус

- `outline: none` без замены запрещён. Кастомный фокус — через `:focus-visible`, кольцо 2–3px с контрастом ≥ 3:1 к соседним цветам, с отступом (`outline-offset: 2px`).
- Skip link «Перейти к основному содержимому» — первый фокусируемый элемент.
- Порядок фокуса = визуальный порядок; положительный `tabindex` не используй; `tabindex="-1"` — для программного фокуса.
- Модалка: фокус внутрь, ловушка фокуса, Esc закрывает, фокус возвращается на кнопку-открыватель.
- Горячие клавиши из одной буквы — с возможностью отключить (2.1.4).

## Семантика и ARIA

- **Первое правило ARIA:** если есть нативный элемент — используй его. `<button>` для действий, `<a href>` для переходов, `<label for>` для полей, `<h1>`–`<h6>` по иерархии, `main`/`nav`/`header`/`footer`.
- Не меняй нативную семантику; любой ARIA-контрол должен работать с клавиатуры (Enter и Space для кнопки); не вешай `aria-hidden` на фокусируемое.
- Иконочная кнопка — с доступным именем: `aria-label="Закрыть"` или скрытый текст.
- Статусы и тосты — `role="status"`; срочные ошибки — `role="alert"`.
- Ошибка поля связана с ним: `aria-describedby`, `aria-invalid="true"`.

## Мобильная доступность

- Поддерживай системный размер шрифта (Dynamic Type в iOS, font scale в Android) — раскладка не ломается при 200%.
- VoiceOver/TalkBack: у каждого элемента понятное имя, порядок чтения логичен, декоративное скрыто.
- Жесты (свайп, мультитач) дублируются кнопками.
- Не блокируй ориентацию экрана без необходимости (1.3.4).

## Когнитивная доступность

- Простой язык, короткие предложения, одна мысль на абзац.
- Предсказуемость: одинаковые элементы ведут себя одинаково.
- Не ограничивай время без необходимости; сохраняй прогресс.
- Для банка: понятные суммы, подтверждения с итогом операции, без двусмысленных формулировок.

## Частые ошибки

- `div` с onclick вместо кнопки.
- Иконочные кнопки без имени.
- Липкий хедер перекрывает элемент в фокусе (2.4.11).
- Капча или запрет вставки в поле пароля (3.3.8).
- Только drag-and-drop без кнопок (2.5.7).
- Тултип с важной информацией только при наведении мыши.
- Контраст проверен на макете, но не на реальных данных и фото.
