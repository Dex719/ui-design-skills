# 08. Анимация и микровзаимодействия

> Каталог конкретных эффектов с параметрами — `21-microinteractions-effects.md`, игровые — `22-game-vfx-juice.md`, готовый код — `assets/effects/`.

Источники: NN/g (animation duration), Material 3 Motion (MDC-Android), web.dev, MDN, Apple HIG.

## Зачем анимация

Анимация объясняет, а не украшает: откуда появился элемент, куда ушёл, что изменилось, что можно сделать. Если анимацию нельзя объяснить одной из этих причин — она лишняя.

## Длительности

| Что | Длительность |
|---|---|
| Микрообратная связь (hover, нажатие, чекбокс, тогл) | ≈ 100 мс (50–150) |
| Небольшие изменения (тултип, раскрытие меню) | 150–250 мс |
| Крупные изменения (модалка, bottom sheet, смена экрана) | 200–300 мс |
| Большие перемещения на широком экране | до 400 мс |
| От ~500 мс | ощущается затянутой (кроме намеренных акцентов) |

- **Выход короче входа:** например 300 мс на появление, 200–250 мс на исчезновение.
- Чем больше расстояние и площадь движения, тем дольше; на мобильных короче, чем на десктопе.

**Токены M3:** short1–4 = 50/100/150/200 мс · medium1–4 = 250/300/350/400 · long1–4 = 450/500/550/600 · extraLong1–4 = 700/800/900/1000.

## Кривые (easing)

| Ситуация | Кривая |
|---|---|
| Элемент появляется / входит на экран | ease-out (быстро стартует, замедляется) |
| Элемент уходит | ease-in (разгоняется и исчезает) |
| Элемент перемещается в пределах экрана | ease-in-out / standard |
| Линейная | только для непрерывных процессов (прогресс, вращение спиннера) |

**Кривые M3:**
- standard `cubic-bezier(0.2, 0, 0, 1)`
- standard-decelerate `cubic-bezier(0, 0, 0, 1)` · standard-accelerate `cubic-bezier(0.3, 0, 1, 1)`
- emphasized-decelerate `cubic-bezier(0.05, 0.7, 0.1, 1)` (вход) · emphasized-accelerate `cubic-bezier(0.3, 0, 0.8, 0.15)` (выход)

**Пружины.** M3 (MDC-Android 1.13+) и iOS используют физические пружины: пространственные (позиция, размер) с лёгким перелётом, эффектные (цвет, прозрачность) без перелёта. Пружины естественнее для жестов: продолжают скорость пальца.

## Производительность

- Анимируй только `transform` и `opacity` — они обрабатываются композитором. Анимация `top/left/width/height` вызывает перерасчёт раскладки и теряет кадры.
- `will-change` — точечно, только при реальной проблеме, и снимай после анимации.
- Цель — 60 fps (16,7 мс на кадр); на 120-Гц экранах любые подлагивания заметнее.

## Доступность движения

- Уважай `prefers-reduced-motion: reduce`: замени движение на затухание (fade), убери параллакс, зум, автопрокрутку, отскоки. Обратную связь не убирай совсем.
- WCAG 2.2.2: автоматическое движение дольше 5 с параллельно с контентом — нужна пауза.
- WCAG 2.3.1: не больше 3 вспышек в секунду.
- WCAG 2.3.3 (AAA): анимация от взаимодействия (параллакс при скролле) должна отключаться.

```css
@media (prefers-reduced-motion: reduce){
  *,*::before,*::after{
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

## Микровзаимодействия

Структура (по Дэну Сафферу): **триггер → правила → обратная связь → циклы/режимы**.

- Кнопка: реакция на нажатие мгновенно (scale 0.97–0.98 или затемнение), загрузка — спиннер внутри, успех — галочка или переход.
- Тогл: ручка перемещается, меняется цвет, состояние читается без цвета (позиция, иконка).
- Поле: фокус — рамка/кольцо, ошибка — встряска 1 раз (или без неё при reduced motion) + текст.
- Добавление в корзину: элемент «летит» в иконку корзины или бейдж увеличивается — связывает действие с местом результата.
- Pull-to-refresh, swipe-to-delete — с видимым порогом срабатывания и Undo.

## Частые ошибки

- Одинаковые 300 мс и `ease` на всё.
- ease-in на появлении (интерфейс кажется заторможенным).
- Анимации, блокирующие ввод (пользователь ждёт, пока «доиграет»).
- Бесконечные пульсации и мигания, отвлекающие от задачи.
- Параллакс и scroll-jacking на всём лендинге.
- Игнорирование reduced motion.
