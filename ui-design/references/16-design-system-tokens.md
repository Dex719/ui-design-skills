# 16. Дизайн-система и токены

Источники: W3C Design Tokens Community Group (Format Module 2025.10), отраслевая практика (Material, Primer, Polaris).

## Стандарт токенов

**W3C DTCG Format Module 2025.10** — первая стабильная версия спецификации (28.10.2025). Поддерживает темы и мультибренд, современные цветовые пространства (OKLCH, Display P3), алиасы, генерацию под web, iOS, Android, Flutter.

```json
{
  "color": {
    "blue": { "500": { "$type": "color",
                       "$value": { "colorSpace": "oklch", "components": [0.546, 0.215, 262.9], "hex": "#2563eb" } } },
    "bg":   { "accent": { "$type": "color", "$value": "{color.blue.500}" } }
  }
}
```

Из выбранного варианта системы `scripts/style_tiles.py --export` пишет такой файл сам — `tokens.json`, вместе с CSS-переменными и `tailwind.css` для Tailwind v4.

## Три уровня токенов

| Уровень | Пример | Кто ссылается |
|---|---|---|
| Примитивные (palette) | `blue-500`, `space-4`, `radius-md` | Только семантические токены |
| Семантические (роль) | `color-bg-danger`, `color-text-secondary`, `space-section` | Компоненты |
| Компонентные | `button-primary-bg`, `input-border-focus` | Конкретный компонент |

Компоненты **не** ссылаются на примитивы напрямую — иначе тёмная тема и ребрендинг ломаются. Имена — по назначению (`text-danger`), а не по виду (`red-text`).

## Минимальный набор

**Цвет**
- Neutral: 9–11 тонов (50…950).
- Primary (brand): 9 тонов.
- Semantic: success, warning, error, info — по 3 роли (bg / border-icon / text).
- Поверхности: `bg`, `surface`, `surface-raised`, `overlay`.
- Текст: `text-primary`, `text-secondary`, `text-tertiary`, `text-on-accent`, `text-disabled`.
- Две темы (светлая и тёмная) на одних семантических именах.

**Типографика:** Display, H1–H3, Body L, Body, Small, Label/Overline — каждый как связка «размер / межстрочный / вес / трекинг».

**Пространство:** 4, 8, 12, 16, 24, 32, 48, 64, 96 px.

**Формы:** радиусы 4 / 8 / 12 / 9999; тени sm / md / lg; толщина рамок 1 / 2.

**Движение:** длительности short / medium / long; 2–3 кривые (см. `08-motion-interaction.md`).

**Слои (z-index):** dropdown, sticky, overlay, modal, toast, tooltip — фиксированная шкала.

## Матрица состояний компонента

| Состояние | Что меняется | Обязательно |
|---|---|---|
| Default | — | — |
| Hover | Фон/рамка на шаг темнее или светлее | Только для указателя |
| Focus | Кольцо фокуса 2–3px, `:focus-visible`, контраст ≥ 3:1 | Да |
| Active / Pressed | Ещё на шаг темнее, лёгкое смещение или scale | Да |
| Selected / Checked | Заливка, галочка, позиция — не только цвет | Для переключаемых |
| Disabled | Сниженный контраст, без hover, курсор `not-allowed` | Объясни, почему неактивно (тултип/текст) |
| Loading | Спиннер внутри, ширина сохраняется, повторный клик заблокирован | Для асинхронных |
| Error | Красная рамка + иконка + текст ошибки | Для полей |
| Read-only | Без рамки или приглушённо, текст можно выделить | Для полей |

## Компоненты: минимальный кит

Кнопка (4 варианта × 3 размера), поле ввода, textarea, select, чекбокс, радио, переключатель, табы, бейдж, тег/чип, тултип, модалка, bottom sheet, тост/баннер, карточка, таблица, пагинация, хлебные крошки, аватар, скелетон, пустое состояние.

## Документация компонента

Для каждого: назначение, когда использовать и когда нет, анатомия, варианты, состояния, поведение (клавиатура, фокус), доступность (роль, имя), тексты, примеры «правильно / неправильно».

## Частые ошибки

- Компоненты ссылаются на примитивы.
- Токены без описаний и правил применения.
- Компонент без состояний focus, disabled, loading, error.
- «Snowflake» — компонент, сделанный под один экран и потом размноженный копиями.
- Дизайн-система живёт только в Figma и расходится с кодом.
