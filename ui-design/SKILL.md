# UI/UX-дизайн: полная версия

Справочник для проектирования интерфейсов, которые понятны с первого взгляда, удобны в работе и выглядят цельно. Основа — когнитивная психология (Круг, Норман, законы UX), визуальная иерархия (CRAP, Refactoring UI), стандарты (WCAG 2.2, Material 3, Apple HIG, Xbox Accessibility Guidelines) и проверенные числа.

Подробности лежат в `references/`. Скрипты запускай из базовой папки скилла (`python3 scripts/…`; в Windows — `python` или `py -3`). **Не читай всё подряд**: открой `MAP.md`, выбери маршрут под задачу и прочитай только нужные файлы.

## Процесс

1. **Определи контекст.** Что за продукт (сайт, лендинг, приложение, дашборд, игра)? Платформа (веб, iOS, Android, десктоп, консоль, ТВ)? Главная задача экрана и одно главное действие? Аудитория (новички, профи, люди с ослабленным зрением, финансы)?
2. **Выбери маршрут в `MAP.md`** и прочитай указанные файлы.
3. **Система до экранов.** Прежде чем верстать, выведи из брифа систему по `references/23`: плотность → размеры и шкала → отступы → формы → цвет → глубина → движение. Каждое значение — с причиной, в `system.json`. Шаблонов нет. Собери 2–3 варианта, которые различаются минимум по трём осям, и покажи их: `python3 scripts/style_tiles.py a.json b.json c.json -o tiles.html`. После выбора экспортируй систему (`--export a.json -d design/`) и строй всё только на её токенах. Если пользователь недоступен, выбери сам и напиши, какой вариант и почему.
4. **Сначала структура, потом стиль.** Контент и задачи → иерархия и группировка → сетка и отступы → типографика → цвет → изображения → анимация.
5. **Спроектируй все состояния**, а не только идеальное: пусто, загрузка, ошибка, офлайн, крайние данные, фокус с клавиатуры/геймпада.
6. **Проверь по чек-листу** (`references/17-audit-testing.md`) перед тем, как отдавать результат.

## Золотые правила

1. **Не заставляй думать.** Кликабельное выглядит кликабельным, статичное — нет. Каждое действие даёт реакцию ≤ 100 мс.
2. **Одна главная цель на экран** — одна Primary-кнопка. Остальное визуально тише.
3. **Иерархия — весом и цветом**, не только размером. Ослабляй второстепенное, а не раздувай главное.
4. **Внутренние отступы меньше внешних.** Группировка видна без рамок.
5. **Шкала отступов 4/8:** 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96. Начинай с избытка воздуха.
6. **Выравнивай всё по общим линиям.** Длинный текст не центрируй.
7. **Контраст:** текст ≥ 4.5:1, крупный текст и элементы UI ≥ 3:1. Текст на фото — по худшему участку кадра.
8. **Смысл не только цветом:** ошибка = цвет + иконка + текст.
9. **Типографика из задачи:** база по расстоянию и аудитории (данные 13–14, приложение 16, iOS 17, чтение и 55+ 18–20), шкала по числу уровней и ширине экрана (×1.2 мобильный, ×1.25 приложение, ×1.333 медиа, ×1.5 промо на десктопе), межстрочный 1.5–1.6 для текста и 1.05–1.25 для крупных заголовков, строка 45–75 символов, 1–2 гарнитуры (`references/23`, раздел 1).
10. **Цели нажатия:** 44×44 pt (iOS) / 48×48 dp (Android); минимум 24×24 CSS px по WCAG 2.2.
11. **Стандартные паттерны для стандартных задач** (закон Якоба). Новаторствуй в ценности, а не в кнопке «Назад».
12. **Меньше вариантов за раз** (закон Хика), прогрессивное раскрытие.
13. **Лейбл над полем, всегда видимый; подсказка — визуальная, а не текстом.** Формат показывает серый пример в поле (`+7 777 123 45 67`), а не абзац под ним («номер можно вставить в любом виде»). Ошибка — после ухода с поля, рядом с ним, **коротко и по факту**: «Недостаточно средств», «Неверный код». Как исправить — только если человек сам не догадается (формат, требования к паролю). Не советуй очевидное («попробуйте пополнить баланс»), не пиши «Ошибка:» и восклицательные знаки, не дублируй смысл пояснениями: каждая строка текста на экране должна быть нужна.
14. **Кнопки — глагол + объект.** «Оплатить 12 500 ₸», а не «ОК».
15. **Сколько движения — решение из брифа, а не «чем больше, тем живее».** Сначала выбери уровень (`references/21`, «Уровень движения»). **Официальные продукты — банк, госуслуги, страхование, медицина, юристы, любой шаг оплаты — минимальный уровень:** отклик на нажатие, смена состояний контролов, загрузка в кнопке, появление модалки или шторки и одна галочка после успешной операции. Без каскадного входа, счёта денежных сумм, тряски полей, бликов, пульсаций и праздников: лишнее движение в таком продукте снижает доверие. Остальные продукты — сдержанный, продуктовый или выразительный уровень.
16. **Анимация при наведении запрещена по умолчанию.** При hover меняются только цвет, фон, рамка или толщина подчёркивания — мгновенно или за ≤ 150 мс. Никакого движения: подъёма карточек, сдвига, масштаба, наклона, «магнита», тени-подъёма, бликов и анимированного подчёркивания по наведению. Добавлять hover-анимацию можно только если пользователь сам об этом попросил.
17. **Анимация объясняет, а не украшает:** 100–300 мс, вход ease-out, выход ease-in, только `transform`/`opacity`, уважай `prefers-reduced-motion`. Эффекты бери из `assets/effects/` (каталог — `references/21`, игровые — `references/22`): тряска поля только вместе с текстом ошибки, частое действие — без анимации, ничего бесконечного.
18. **Один визуальный язык:** один набор иконок, один стиль фото, одни радиусы и тени для фото и карточек.
19. **Никаких эмодзи.** Ни в кнопках, ни в заголовках, ни в пустых состояниях, ни в игровых слотах. Символы, которые браузер рисует как эмодзи (★ ✓ ✕ ⚠ ⚡ ❤ ☰ ⋯), тоже нельзя. Нужна иконка — возьми из `assets/icons` (`python3 scripts/icon.py <имя>`), скачай из открытого набора того же стиля (Lucide, Tabler, Phosphor, Material Symbols; для игр — game-icons.net, Kenney) или нарисуй SVG 24×24 с той же обводкой (`references/09`, «Иконки»).
20. **Всё из токенов:** цвета, отступы, шрифты, радиусы — по семантическим именам, обе темы.
21. **Цвет — решения из брифа, значения — из скрипта.** Тон (из смысла и в стороне от конкурентов), хрома (из энергии), температура нейтралей, светлая или тёмная тема, схема светлоты акцента — по `references/23`, раздел 4. HEX считает `make_palette.py`, контраст проверяет `check_contrast.py`. Один акцент ≤ 10% экрана, тонированные нейтрали. Без индиго, бирюзы и синего «по привычке»; варианты различаются минимум по 3 из 5 признаков палитры.
22. **У каждого значения есть причина.** Размер, шкала, отступ, радиус, тень, тон записываются вместе с «почему» из брифа. Если причины нет, это привычка, а не решение. Новое значение сначала добавляется в систему, потом в макет.
23. **Пропорции считаются:** H1 ≥ 1.6× текста; межстрочный и трекинг падают с ростом размера; отступы растут в 1.5–2 раза по уровням вложенности; высота контролов одна в ряду; радиус от высоты (h/6 нейтрально, h/2 таблетка), вложенный = внешний − отступ.
24. **Кнопки по месту:** главная кнопка формы — в конце, по левому краю полей; в диалоге — справа, порядок по платформе и единый во всём продукте; на мобильном главное действие внизу; разрушительное — отдельно и не по Enter (`references/23`, раздел 5).
25. **Клавиатура и геймпад — полноправный ввод:** видимый фокус, логичный порядок, без ловушек.
26. **Без тёмных паттернов:** отказ так же лёгок, как согласие; никаких фейковых таймеров и предвыбранных галочек.
27. **Одна смелая идея** (шрифт, цвет или композиция) вместо набора модных эффектов — так дизайн не выглядит шаблонным.

## Ключевые числа

| Что | Значение |
|---|---|
| Отклик | 0,1 с — мгновенно · 0,4 с — порог Доэрти · 1 с — нужен индикатор · 10 с — прогресс + отмена |
| Контраст WCAG AA | 4.5:1 текст · 3:1 крупный текст (≥ 24px / ≥ 18.66px bold) и UI · AAA 7:1 |
| Базовый текст | Веб 16px · M3 16/14sp · iOS 17pt · поле ввода в iOS ≥ 16px |
| Длина строки | 45–75 символов (`max-width: 65ch`) |
| Цели нажатия | 44 pt · 48 dp · WCAG 24 CSS px · мобильные игры ≥ 15 мм |
| Анимация | 100 мс микро · 200–300 мс модалки · ≤ 400 мс крупное · выход короче входа |
| Core Web Vitals | LCP ≤ 2,5 с · INP ≤ 200 мс · CLS ≤ 0,1 |
| OG-изображение | 1200×630 |
| Игры: текст | Консоль 1080p ≥ 26 px · ПК 1080p ≥ 18 px · субтитры ≥ 46 px, ≤ 40 знаков, ≤ 2 строки |
| Игры: safe area | Title-safe 90% (1728×972 при 1080p) · action-safe 95% (1824×1026) |
| Вспышки | ≤ 3 в секунду |
| Юзабилити-тест | 5 человек ≈ 85% проблем · SUS среднее 68 |

## Как отдавать результат

**Если генерируешь макет или код:**
- Цвета, отступы, радиусы, шрифты — переменными (`:root` / токены), светлая и тёмная тема. По умолчанию тема как в системе (`prefers-color-scheme`); ручной переключатель только переопределяет её.
- Все интерактивные элементы — со всеми состояниями (hover, focus-visible, active, disabled, loading, error).
- Движение — только из выбранного уровня (`references/21`), через `assets/effects/`. Проверь, что ничто не меняется рывком и что нет эффектов сверх уровня.
- **Встраивай только нужное.** В проект с файлами подключай `effects.css`/`effects.js` целиком. В одностраничный файл копируй только используемые функции `fx` (с их вспомогательными) и их CSS-классы, а иконки — только нужные: `python3 scripts/icon.py --sprite --only bell,user,x`. Вся библиотека и весь спрайт утяжеляют страницу в 3–5 раз.
- Семантический HTML, `alt` у изображений, `width`/`height` у медиа, `prefers-reduced-motion`.
- Реалистичный контент (длинные имена, суммы, пустые списки), а не только «идеальный» Lorem ipsum.

**Если делаешь ревью:**
- Находки по приоритету: критично → серьёзно → незначительно → косметика.
- Для каждой: где, что не так, какое правило нарушено (со ссылкой на закон или критерий), как исправить.
- Начинай с задачи и иерархии, а не с цвета кнопки.

## Карта

`MAP.md` — все файлы, маршруты по типам задач (обязательное и по необходимости) и указатель тем. `references/SOURCES.md` — первоисточники.

## Инструменты скилла

- `scripts/style_tiles.py` — варианты стиля рядом из твоих `system.json` (проверяет причины, пропорции, шаблонные тона и непохожесть вариантов), `--export` пишет `design-system.css`, `DESIGN.md`, `tokens.json` (W3C DTCG 2025.10) и `tailwind.css` (Tailwind v4 `@theme`, имена shadcn/ui), размеры шрифта — в rem, `--embed-fonts` встраивает шрифты для офлайна. Схема — `references/23`, пример — `assets/styles/system.example.json`.
- `scripts/icon.py` + `assets/icons/` — 127 иконок Lucide (ISC) inline-SVG и спрайтом; вместо эмодзи.
- `scripts/make_palette.py` — палитра (светлая + тёмная) из тона и хромы акцента, нейтрали Radix, контраст подгоняется автоматически.
- `scripts/build_palettes.py` — пересобирает 17 палитр и таблицу в `references/20` из `assets/palettes/palettes.json` (`--check` для CI).
- `scripts/build_motion_override.py` — добавляет в CSS режим «анимации включены вручную» (`<html data-motion="full">`), даже если в системе стоит «уменьшить движение».
- `scripts/check_contrast.py` — проверка контраста пары цветов или всех токенов в CSS/HTML-файле.
- `assets/palettes/*.css` — 17 примеров палитр для калибровки (не шаблоны): как тон, хрома, нейтрали, яркий акцент и тёмная тема по умолчанию меняют звучание. `make_palette.py --bright` (яркий акцент с тёмным текстом), `--dark-first` (тёмная тема по умолчанию).
- `assets/effects/effects.css` + `effects.js` — библиотека эффектов (`window.fx`): тряска поля с ошибкой, кнопка → успех (зелёная с галочкой), галочка успеха, кнопка-загрузка, копирование, тосты, модалка, аккордеон, вкладки, скелетон, счётчики, каскад, колокольчик уведомлений, бейджи, блик, конфетти, вход страницы, FLIP-сортировка, прорисовка графиков, смена темы, игровые: тряска по «травме», вспышка, хитстоп с дрожью, цифры урона по типам, HP с «призраком», частицы, цветной оттенок (лечение, яд, мороз), ударные волны, радиальные линии, вспышка экрана, зум-панч, замедление времени, штампы «КРИТ!», остаточные изображения, световой столб, монеты по дуге, прыжок. Все уважают «уменьшить движение». `assets/effects/demo.html` — живые примеры.
